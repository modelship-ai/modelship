modelship has been installed as release "{{ .Release.Name }}" in namespace "{{ .Release.Namespace }}".

A RayCluster ({{ include "modelship.fullname" . }}) is starting, and the Job {{ include "modelship.fullname" . }}-deploy-{{ .Release.Revision }}
deploys the models from your models.yaml through the head's dashboard, once the
head is up.

1. Watch the cluster come up. A worker hosting no replica stays 0/1 Ready, so the
   RayCluster doesn't report ready while one does:

   kubectl get pods -n {{ .Release.Namespace }} -l ray.io/cluster={{ include "modelship.fullname" . }} -w

2. Track the deploy (model download + load can take a while). Helm waits for it
   only with `--wait --wait-for-jobs`:

   kubectl get job -n {{ .Release.Namespace }} {{ include "modelship.fullname" . }}-deploy-{{ .Release.Revision }}
   kubectl logs -n {{ .Release.Namespace }} job/{{ include "modelship.fullname" . }}-deploy-{{ .Release.Revision }} -f

3. Reach the OpenAI-compatible gateway (/readyz returns 503 until models load).
   It's mounted under its gateway name, so with gateway.name={{ .Values.gateway.name }}:

   kubectl port-forward -n {{ .Release.Namespace }} svc/{{ include "modelship.fullname" . }}-gateway {{ .Values.gateway.port }}:{{ .Values.gateway.port }}
   curl http://localhost:{{ .Values.gateway.port }}{{ include "modelship.gatewayPath" . }}/v1/models

{{- if eq .Values.service.type "ClusterIP" }}

   (Service type is ClusterIP — use port-forward above, or set service.type to
   LoadBalancer/NodePort to expose it outside the cluster.)
{{- end }}

4. Ray's dashboard and cluster RPC require the cluster's auth token:

   kubectl get secret -n {{ .Release.Namespace }} {{ include "modelship.rayAuthSecretName" . }} -o jsonpath='{.data.auth_token}' | base64 -d

5. Apply models.yaml changes later by re-running with your updated values:

   helm upgrade {{ .Release.Name }} <chart> -n {{ .Release.Namespace }} -f your-values.yaml

{{- if not (index .Values "kuberay-operator" "enabled") }}

NOTE: this chart assumes the KubeRay operator + CRDs are already installed in the
cluster. If `kubectl get rayclusters` errors with "no matches for kind", install
the operator (once, cluster-wide) or set `kuberay-operator.enabled=true`.
{{- end }}

{{- if not .Values.workerGroups }}

WARNING: workerGroups is empty. The head runs the `thin` image (no torch/vllm) and
never schedules models — with no worker groups, this cluster deploys ZERO model
